## 一、参照站的页面组织（据四张截图与站点源码）

### 1. 顶部导航：**一条平的九模块栏**，没有第二套壳

`首页 · 地图 · 数据资源 · 算子模型 · 算力平台 · 案例 · 工作台 · 开放社区 · 个人中心`
右侧固定：主题切换 · `EN` · `登录` · `注册`（登录后变成用户槽）。

站点源码里没有"门户 shell / 地球 shell"的区分：**同一套导航、同一套页面骨架**，
地图只是其中一个模块。

### 2. 每页统一骨架

```
页面头部    大标题（如「案例」「数据资源」） + 一句话说明 + 右侧动作/状态
主体        三种之一：
            ① 筛选/工具栏 + 卡片栅格   —— 数据资源
            ② 左列表 + 右详情（dossier）—— 案例
            ③ 左输入 + 右结果          —— 工作台
地图        只在"地图"模块全屏；其它模块里作为**内联卡片**出现（工作台右下「空间范围」，
            案例详情里的地图块），不是当背景
```

### 3. 各模块的信息层级

| 模块 | 参照站的做法 |
|---|---|
| 首页 | 左文案 + 右地球的两栏；一句主张做标题；三张能力卡（卫星智能分析 / SDG 评估 / 地理知识问答）；一个主 CTA「浏览公开案例」；下方「了解…」板块 |
| 地图 | 全屏地球 + 浮层控件（顶栏、状态 chip、左侧意图条、右侧实例详情与分阶段面板），面板浮在地球上而不是切走地球 |
| 数据资源 | 头部 + **带计数的筛选页签**（全部 30 / 栅格 18 / 矢量 7 / 统计数 5）+ 搜索 + 三个下拉 + 视图切换；一行汇总（共 30 项…）；**四列卡片**：类型标签 + 预览区（无则诚实写「暂无预览」）+ 标题 + 描述 + 字段（时间范围/空间分辨率/来源机构）+ 页脚（权属方 + 查看详情） |
| 案例 | 头部一句话说明；**左窄栏列表**（标题 + 副标题 + 状态标签「存档」，选中高亮）；**右宽栏 dossier**：标题 + 结果性质提示条 + 研究区域 + 问题 + **所用数据（表格：机构 / 节点）** + **处理过程（编号步骤 + DISCOVER/EXECUTE + 技能标识）** |
| 工作台 | 头部：名称 + 「已保存」标签 + 副标题（工作流·修订·节点数）+ 右侧「本地执行」标签与 保存/运行；**页签 提问/编辑/代码**；左栏：任务描述框 + 从当前工作流继续（两张提示卡）+ 输入区（Enter 发送提示）；右栏：**节点列表**（序号 + 名称 + 参数 + 来源标签） + **空间范围地图卡**（真实地图 + AOI 矩形 + 20km 比例尺） |

### 4. 视觉语言

- 深色底；页面大标题（约 32–40px，粗）；标题下一行灰色说明；
- 卡片：圆角、细边框、右上或左上小标签（类型/状态）；字段用**等宽小字**；
- 状态标签语义化（存档 / 已保存 / 规划服务可用 / 本地执行）；
- 空状态不糊弄：`暂无预览`、`权属方未提供`、`无法按更新时间排序：目录未记录…`。

## 二、我们现在的问题（对照结论）

1. **两套导航、概念重复**：`nav.js` 里有三组 16 项 ——「全球门户」9 个模块 + 「莫干地球系统」6 个页面 + 管理。
   同一个概念出现两次：`global-cases` 与 `cases`、`data-resources` 与 `geocards`、`visual-earth` 与 `map`。
   用户要在两套壳之间切换，这就是"页面组织混乱"的根源。
2. **一切塞进左侧抽屉**：`EarthLayout` 用固定 ~360px 抽屉承载列表 + 详情 + 四级图层 + 运行记录，
   主体（地球/地图）反而被挤到剩下的一条；案例页在抽屉里同时出现"案例列表"和"图层面板"，层级不清。
3. **地图/地球是背景而不是上下文**：除了地图页，其它模块没有内联地图；反过来在地图页上又缺参照站那种浮层面板（右侧实例详情/分阶段面板）。
4. **缺统一页面头部**：我们的页面没有"大标题 + 一句说明 + 右侧动作"的固定头部，视觉上分不出模块。
5. **列表/详情比例失衡**：案例详情现在是一堆 `dl/dt/dd`，没有参照站那种「研究区域 / 问题 / 所用数据 / 处理过程」的分段结构。

## 三、改动清单（按优先级）

### A. 导航与壳（先做，其它改动都挂在它上面）

- [ ] **合并为一套九模块导航**：首页 / 地图 / 数据资源 / 算子模型 / 算力平台 / 案例 / 工作台 / 开放社区 / 个人中心（+ 管理，仅管理员可见）。
      `portalNav` 与 EarthLayout 的 earth 页面合并；旧路由用重定向保留，避免外链失效。
- [ ] 概念归并：`geocards` → 数据资源；`visual-earth` → 地图；`global-cases` + `cases` → 案例；
      `super-agent` → 工作台；`typical-apps` → 案例的推荐区（或首页）。
- [ ] **统一页面骨架组件** `PageShell`：`title` / `subtitle` / `actions` 插槽 + 主体区；所有模块页改用它。

### B. 各模块页

- [ ] **案例页**：左列表（标题 + 地点 + 状态标签）+ 右 dossier（研究区域 / 问题 / 所用数据表 / 处理过程编号步骤 / 交付物 / 图层与地图卡）。
      把现在抽屉里的"四级图层 + 双时间轴 + 几何开关"移到 dossier 的「图层」分段里。
- [ ] **数据资源页**：筛选页签带计数 + 搜索 + 下拉 + 视图切换 + 四列卡片（含诚实空预览）。
- [ ] **工作台页**：页签 提问/编辑/代码；左输入 + 提示卡；右节点列表 + 空间范围地图卡。
- [ ] **地图页**：全屏地球 + 浮层（左意图/图层，右详情/步骤），参照 console 的浮层组织。
- [ ] **首页**：两栏 hero + 三张能力卡 + 主 CTA + 推荐案例。

### C. 视觉

- [ ] 设计令牌统一（深色底、标题/正文/等宽三级字号、卡片与状态标签样式），集中在 `styles/tokens.css`。
- [ ] 状态标签语义化：存档 / 已保存 / 规划服务可用 / 本地执行 / 合成示意。
- [ ] 空状态文案规范（不糊弄）。

### D. 验收

- [ ] 与参照站逐屏对照截图（首页/地图/数据资源/案例/工作台），差异清单化；
- [ ] 平台 API 测试与前端 vitest 全绿；改版不影响已完成的案例可视化（四级 LOD、几何开关、PC1 图例、可见性分层）。
